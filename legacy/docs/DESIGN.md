# 整体设计：工作类型、组合、资料夹与范本（草案，待确认）

> 状态：**设计草案**（2026-10-21）。确认后才会搬移现有资料、改写程式。

## 一、三种工作类型

每一份工作（job）属于下面其中一类，放在工作区对应的资料夹里，互不干扰：

| 类型 | 资料夹 | 你给的 | 产出 | 时间以谁为准 |
|---|---|---|---|---|
| **只提取声音** | `extract/` | 影片 | 音档；可选：声音样本、逐字稿、对齐原片的字幕 | 原片 |
| **我给影片，Voicebox 配音** | `dub/` | 影片（画面要保留）＋讲稿（可由原片逐字稿起草） | 新配音、字幕、换掉声音的影片 | **原片画面** |
| **完整生成** | `generate/` | 讲稿／pptx／海报／主题说明，任意组合 | 配音、字幕、影片 | **配音** |

`dub` 和 `generate` 最根本的差别是**时间以谁为准**：
- **dub**：画面已经定了，配音要塞进原片每一段的时间里（调整停顿、必要时微调语速，最后才考虑停格补画面）。
- **generate**：先配音，再依配音长度决定每一幕多长（PDF 第三节的原则）。

只要配音和字幕、不要影片，用 `generate`，在 `job.toml` 里设 `video = false`。

## 二、工作区结构

```text
split-voice-workspace/
├── shared/                       所有工作共用
│   ├── vocabulary.tsv            词汇表：字幕显示 vs Voicebox 念法
│   └── voice/samples/            复制声音的样本
├── extract/<job-name>/
├── dub/<job-name>/
└── generate/<job-name>/
    ├── job.toml                  这份工作的设定（类型、要用哪些输入、要产出什么）
    ├── input/                    你提供、或你确认过的东西（都有范本）
    ├── review/                   等你确认的东西：AI 起草的讲稿、预览图、试听档
    ├── work/                     中间档（每句音档、暂存），可以删、可以重算
    └── output/v1, v2, …          成品，每次输出新版本，不覆盖
```

- **input/**：只放「你决定的事」。程式不会改这里的档案；AI 起草的东西先放 `review/`，你确认后才搬进 `input/`。
- **review/**：所有「需要讨论、需要你点头」的东西都在这里，每一个档案都对应 `input/` 里的一个范本。
- 工作名称（资料夹名）一律小写英文加连字号，例如 `bart-risk-taking`；中文标题写在 `job.toml`。

## 三、所有组合

### 3.1 只提取声音（extract）

| 选项 | 说明 |
|---|---|
| 全片／一段 | `range = ["1:30", "2:10"]`，留空表示全片 |
| 声音样本 | 依停顿切成 10–20 秒，给 Voicebox 建复制声音 |
| 逐字稿 | Whisper 听写（会有同音错字，要人工校对） |
| 对齐原片的字幕 | 有讲稿时：讲稿文字＋原片时间（比单纯 Whisper 准）；没有讲稿：Whisper 文字 |

### 3.2 我给影片，Voicebox 配音（dub）

| 情况 | 讲稿从哪来 | 时间怎么对齐 |
|---|---|---|
| D1 原片有人声，你有讲稿 | 你的讲稿 | 用原片逐字稿把讲稿每一句对到原片时间 |
| D2 原片有人声，没有讲稿 | Whisper 逐字稿 → 起草讲稿 → 你校对 | 同上 |
| D3 原片没有人声（例如只有画面），有讲稿 | 你的讲稿 | 你在讲稿标出每段开始时间，或在 `input/cues.tsv` 填时间 |
| D4 原片是 PowerPoint 汇出的 | — | **建议改用 generate 的 pptx 方式**，换页时间可以跟着新配音走 |

配音塞不进原片时间时，依序：缩短句间停顿 → 语速微调（0.9–1.1 倍）→ 原片停格补时间（会改变画面节奏，要你同意）。每一段的处理结果都列在 `output/vN/timing_report.tsv`。

原片的背景音乐和音效：`keep_background = true` 时保留原片声音、压低音量混在配音下面（原片人声会一起被保留，只适合原片没有人声的情况）；预设不保留。

### 3.3 完整生成（generate）

**讲稿来源**（四选一）：

| 代号 | 讲稿来源 | 需要你确认 |
|---|---|---|
| S1 | 你写好的讲稿 `input/script.md` | 不用 |
| S2 | 从 pptx 的备忘稿（speaker notes）或页面文字起草 | `review/script.md` |
| S3 | 从海报／论文内容起草 | `review/script.md` |
| S4 | AI 依主题说明 `input/brief.md` 自主撰写 | `review/script.md`（并标出需要查证的事实） |

**画面来源**（可以混用，每一幕各自指定，见 `input/scenes.toml`）：

| 代号 | 画面来源 | 怎么做 | 适合 |
|---|---|---|---|
| V1 | **PowerPoint 汇出** | 依配音设定换页与 `[click]` 动画时间，PowerPoint 自动汇出；先移除 pptx 内嵌的旧录音 | 有动画、转场的简报 |
| V2 | **pptx 当分镜＋海报原图** | 从 pptx 读每页的裁切位置和提示栏文字 → 用高解析海报渲染（镜头移动） | 你这份「心研法海報-slide」：同一张海报不同裁切＋Morph 转场 |
| V3 | **海报自动对位** | 讲稿每一幕的文字对到海报上的段落 → 镜头框；你在预览图上确认 | 只有海报 |
| V4 | **AI 版面（HTML + GSAP）** | AI 依每一幕的内容写画面，HyperFrames 渲染 | 没有任何视觉素材，或想要动画图表 |
| V5 | **生成式影片片段** | Veo／Runway 等服务生成，只当插播 | 片头、情境画面 |
| V6 | **你给的图片／影片片段** | 指定插在哪一幕 | 截图、示范操作 |

**你给的素材 → 预设怎么做**（`job.toml` 的 `visual = "auto"` 时）：

| 讲稿 | pptx | 海报 | 预设流程 |
|---|---|---|---|
| ✔ | — | — | V4 文字画面（或只出配音） |
| ✔ | ✔（有动画） | — | V1 PowerPoint 汇出 |
| ✔ | ✔（同一张图不同裁切） | — | V2，但画面用 pptx 里的图（解析度较低，会提醒你给海报原档） |
| ✔ | — | ✔ | V3 海报自动对位 |
| ✔ | ✔ | ✔ | V2 pptx 分镜＋海报原图（**你现在的情况**） |
| — | ✔ | — | S2 起草讲稿 → 你确认 → V1 |
| — | — | ✔ | S3 起草讲稿 → 你确认 → V3 |
| — | ✔ | ✔ | S2/S3 起草讲稿 → 你确认 → V2 |
| — | — | — | S4 依主题说明 → 你确认 → V4（可加 V5 插播） |

**怎么判断 pptx 是哪一种**：每一页都只有同一张大图、只是裁切不同 → 当分镜（V2）；有一般的文字、图表、点击动画 → PowerPoint 汇出（V1）。判断结果写在 `review/pptx_report.md`，你可以在 `job.toml` 强制指定。

**字幕与输出**（每一种组合都适用）：字幕要不要烧进画面、要哪几种格式（YouTube／PowerPoint／VLC）、响度（YouTube −14、简报 −16）、只出配音不出影片。

### 3.4 每一种都会经过的确认点

```text
  起草讲稿 ──► [确认 1] 讲稿 ──► 词汇检查 ──► [确认 2] 难念的词（试听）
     ──► 配音 ──► [确认 3] 逐句听写报告（有问题的句子试听、挑版本）
     ──► 分镜 ──► [确认 4] 每一幕预览图（镜头框、提示栏文字）
     ──► 渲染 ──► [确认 5] 成品：缩图总览＋验收报告
```

你给的东西已经确定的，那一关就自动跳过（例如你给了讲稿，就没有确认 1）。每一关都有一个 `review/` 档案让你看、一个 `input/` 范本让你改。

## 四、需要你提供／确认的资料与范本

所有范本都在程式的 `templates/` 里，`init` 指令会依工作类型复制到 `input/`。每个范本：
- 开头写清楚「这是什么、哪些栏位必填、填错会怎样」；
- 附一个完整的范例；
- 栏位名称固定、都是英文，值可以是中文；
- 有对应的检查指令，格式错误会说出**第几行、哪个栏位、该怎么改**（让 Ollama 和人都不用猜）。

| 范本 | 用在 | 内容 |
|---|---|---|
| `job.toml` | 全部 | 类型、标题、要用哪些输入、画面方式、字幕、输出 |
| `brief.md` | generate S4 | 主题、观众、长度、语气、一定要讲的重点、可用的资料来源、禁止事项 |
| `script.md` | dub、generate | 讲稿格式（投影片、段落、`[click]`、`{{词汇}}`） |
| `scenes.toml` | generate | **每一幕要怎样**：画面来源、海报区域、提示栏、画面上的文字、插播、你的备注 |
| `cues.tsv` | dub D3 | 每一段在原片的开始时间 |
| `vocabulary.tsv` | 共用 | 特殊词：字幕显示、Voicebox 念法、类型、试听日期 |
| `extract.toml` | extract | 范围、要不要样本／逐字稿／字幕 |

## 五、PDF 工作流需要修正或补充的地方

PDF（陈文盛，2026-09-21）的七个步骤和避坑清单大致正确，以下是依我们实际做过的结果需要修正或补充的地方：

| # | PDF 的说法 | 问题 | 修正 |
|---|---|---|---|
| 1 | 量时长：用 ffprobe 量每一句配音几秒 | TTS 原始音档头尾有静音，有时还会吞掉句子头尾 | 每句前后加 marker 生成、只在静音处切掉 marker，**切完再量**；量之前先用 Whisper 逐句检查 |
| 2 | 每页长度 = 旁白长度 + 0.8 秒喘息 | 固定停顿：段落结束太快、句中逗号又太慢 | 依标点决定：段落 0.85、句号 0.5、分号 0.4、逗号 0.25 秒；换页至少 0.85 秒 |
| 3 | 验收（第 7 步）在渲染之后才做 | 配音错了要等渲染完才发现，白跑一趟 | **配音阶段就逐句验收**（听写比对、头尾残留检查），影片阶段再验一次 |
| 4 | Whisper 逐句核对 | Whisper 会把专有名词听成同音字；给它提示词时，还会在没念到的地方「补」出专有名词 | 比对时容许同音误差、看相似度；专有名词以人耳为准（例如 H1 被听成 HE，实际没错） |
| 5 | 用 Whisper 生字幕（最低成本路线） | 字幕会有同音错字 | **字幕文字用讲稿**、时间用配音的时间轴，完全不靠听写 |
| 6 | 字型用 PingFang TC | 在这台 Mac，苹方是系统私有字型，Python／Pillow 读不到 | HTML（浏览器渲染）可以用苹方；Python 画字幕和提示栏用黑体-繁（Heiti TC） |
| 7 | 用 FFmpeg 合成 | Homebrew 的 ffmpeg 没有 drawtext／libass，不能用 ffmpeg 烧字幕 | 字幕和提示栏用 Python 画成透明图层再叠上去 |
| 8 | 用 npx 取最新版 HyperFrames | 跟 PDF 自己强调的「可重现」矛盾：今天和下个月跑出来可能不一样 | 先用最新版试，**跑通后锁定版本**，版本号写进 `output/vN/versions.txt` |
| 9 | Node 23.3 会当掉、换 Node 25 就好 | SOP 装的是 LTS（目前 v24），PDF 没测过 | 渲染前检查 Node 版本；v24 要先实测 |
| 10 | 成品要复制到会备份的地方 | 只说要复制，没说怎么避免覆盖 | 每次输出新版本 `output/vN/`，不覆盖；`job.toml` 可设定自动复制到备份资料夹 |
| 11 | 配音比较：edge-tts vs ElevenLabs | edge-tts 需要网路，也不是官方公开的 API，随时可能失效；跟「本机执行」的目标不同 | 我们用本机 Voicebox 复制声音；edge-tts 可当备援 |
| 12 | （没提到）PowerPoint 影片 | 「最低成本路线」要手动剪接；PowerPoint 自己的动画时间不会跟着配音 | 用 AppleScript 依配音设定换页时间，`[click]` 动画改成定时触发，PowerPoint 自动汇出；**先移除 pptx 内嵌的旧录音** |
| 13 | （没提到）英文专有名词念不准 | TTS 读英文不稳，而且同一写法每次结果不同 | 词汇表分开定义「字幕显示」和「念法」；难念的句子多生成几个版本挑选 |
| 14 | （没提到）繁体与字幕格式 | 简转繁会误转（只→隻）；PowerPoint 读不了有 BOM 的字幕 | 繁体修正表；所有字幕无 BOM、VTT 不加编号 |
| 15 | lint（第 5 步）是 HyperFrames 专用 | 不用 HyperFrames 的画面方式没有对应的检查 | 每种画面方式都有「渲染前检查」：页数、[click] 数、区域是否在海报内、提示栏长度、词汇 |

PDF 里正确、照做就好的：资讯型影片不要交给生成式模型；先配音再决定画面长度；`-map 0:v:0 -map 1:a:0`；动画不用随机数和当前时间；字型用本机的；渲染前关掉吃记忆体的程式；AI 生成的内容要揭露；素材授权要看清楚。

## 六、实作顺序（确认设计后）

1. 新的工作区结构＋`init`、`check` 指令（依工作类型复制范本、检查格式）。
2. 把现有的 `talks/bart-risk-taking` 搬成 `generate/bart-risk-taking`（内容不动）。
3. generate V2：从 pptx 读分镜（你现在这份）→ 用海报原图渲染。
4. generate V3 海报自动对位、S2/S3 起草讲稿。
5. dub（D1、D2）。
6. extract 补上逐字稿与对齐字幕。
7. V4（HTML + HyperFrames）、V5（生成式影片），以及 Open WebUI 工具对应的新功能。
