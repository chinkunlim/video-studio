# ADR-002：工作區結構隔離與素材審核（Review/Approve）機制

- **狀態**：Accepted
- **日期**：2026-10-22
- **Agent**：`antigravity`
- **任務**：`TASK-002`
- **相關規格**：[`SPEC-003`](../specs/003-templates-and-inputs.md)

## 1. 背景與問題

AI 影音系統在生成講稿、切分分鏡與配音時，常常涉及不可逆的覆寫行為。若 AI 工具直接改寫使用者的原始講稿或分鏡設定，一旦生成效果不佳或解析錯誤，原始素材將無法復原。此外，影音算圖與轉檔耗時，若每次產出都覆蓋舊檔案，使用者將無法比對不同版本的渲染效果。

## 2. 評估過的方案

| 方案 | 優點 | 缺點 |
|---|---|---|
| A. 四層目錄隔離：`input/`（唯讀原始）、`review/`（AI 草稿）、`work/`（中間快取）、`output/vN/`（版本化成品） | 原始資料永不毀損；草稿需人工 `approve` 才生效；成品版本可歷史回溯 | 目錄層級較多，需嚴格檢核函式路徑 |
| B. 覆蓋寫入式：直接在單一目錄下更新 `script.md` 與 `video.mp4` | 目錄結構簡單 | 無法找回舊版本素材，AI 自動草擬時可能毀損人工編輯內容 |
| C. Git 自動 commit 追蹤 | 具備完整版本歷程 | 影音檔案（數百 MB 至數 GB）不適合放入 Git 追蹤 |

## 3. 決策與理由

**採用方案 A**：
1. **`input/` 唯讀化**：所有排程或 AI 工具禁止直接修改 `input/` 內既有檔案。
2. **`review/` 審核緩衝區**：AI 起草的講稿（`review/script.md`）或分鏡檔（`review/scenes.toml`）放置於 `review/`。
3. **`approve` 確認指令**：使用者確認滿意後，呼叫 `approve` 將審核檔覆蓋移入 `input/` 並備份舊檔。
4. **`output/v<N>/` 成品版本遞增**：產出影片與字幕時，自動尋找最大版本號並 `+1` 寫入新資料夾（如 `v1`、`v2`），不破壞過往成品。

## 4. 影響與代價

- **正面影響**：
  - 確保使用者資產安全，解決 LLM 幻覺修改講稿帶來的風險。
  - 中間目錄 `work/` 可隨時手動清空重建，不影響正式成品。
- **代價**：
  - 各個 Service 必須嚴格遵照工作區約定路徑讀寫，不得任意在根目錄散落檔案。
